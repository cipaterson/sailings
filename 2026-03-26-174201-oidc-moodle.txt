# Project: Rails + Moodle Shared Authentication (SSO)                           
                                                                                
## Goal                                                                         
Enable single sign-on between a bespoke Rails app and Moodle, using the Rails   
app as the OIDC identity provider. No additional auth infrastructure (no        
Keycloak, Authentik, etc.).                                                     
                                                                                
## Chosen Approach                                                              
**Rails acts as the OIDC provider** via `doorkeeper` +                          
`doorkeeper-openid_connect` gems. Moodle connects to Rails using the            
`auth_oidc` Moodle plugin.                                                      
                                                                                
## Architecture                                                                 
```                                                                             
User → Moodle → redirects to Rails (/oauth/authorize)                           
             → User logs in to Rails                                            
             → Rails issues token, redirects back to Moodle                     
             → Moodle validates token, logs user in                             
```                                                                             
                                                                                
## Key Implementation Steps                                                     
                                                                                
### Rails Side                                                                  
1. Add gems: `doorkeeper`, `doorkeeper-openid_connect`                          
2. Run generators and migrate:                                                  
   ```bash                                                                      
   rails generate doorkeeper:install                                            
   rails generate doorkeeper:migration                                          
   rails generate doorkeeper:openid_connect:install                             
   rails db:migrate                                                             
   ```                                                                          
3. Configure `config/initializers/doorkeeper.rb`                                
   - `resource_owner_authenticator` returns `current_user` or redirects to      
login                                                                           
   - Grant flow: `authorization_code`                                           
4. Configure `config/initializers/doorkeeper_openid_connect.rb`                 
   - Set issuer to Rails app URL                                                
   - RSA signing key stored in Rails credentials under `oidc.signing_key`       
   - Expose claims: `email`, `name`                                             
5. Generate RSA signing key: `openssl genrsa -out private.pem 2048`, store in   
credentials                                                                     
6. Register Moodle as a Doorkeeper client (in console or seed):                 
   ```ruby                                                                      
   Doorkeeper::Application.create!(                                             
     name: "Moodle",                                                            
     redirect_uri: "https://yourmoodle.com/admin/oauth2callback.php",           
     scopes: "openid email profile",                                            
     confidential: true                                                         
   )                                                                            
   ```                                                                          
7. Mount routes in `config/routes.rb`:                                          
   ```ruby                                                                      
   use_doorkeeper { skip_controllers :applications, :authorized_applications }  
   use_doorkeeper_openid_connect                                                
   ```                                                                          
                                                                                
### Moodle Side                                                                 
- Install `auth_oidc` plugin                                                    
- Configure with Rails endpoints:                                               
  - Discovery URL: `https://yourrailsapp.com/.well-known/openid-configuration`  
  - Or manually set authorize/token/userinfo/jwks endpoints                     
- Enter `client_id` and `client_secret` from Doorkeeper application record      
- Enable JIT (Just-in-Time) provisioning for auto user creation on first login  
                                                                                
## Known Caveats / Outstanding Work                                             
- [ ] Single logout not yet implemented — logging out of one app does not log   
out of the other; requires OIDC back-channel logout                             
- [ ] JIT provisioning in Moodle needs to be verified/enabled                   
- [ ] Rails app becoming a dependency of Moodle — if Rails is down, Moodle      
logins fail; consider implications for maintenance windows                      
- [ ] Test full auth flow end-to-end in staging before production               
                                                                                
## Key URLs (fill in your values)                                               
- Rails app: `https://yourrailsapp.com`                                         
- Moodle: `https://yourmoodle.com`                                              
- OIDC discovery: `https://yourrailsapp.com/.well-known/openid-configuration`   
                                                                                
## Alternatives Considered & Rejected                                           
- **Keycloak** — too heavy, Java/JVM overhead                                   
- **Authentik** — not significantly lighter (needs Redis + worker + db)         
- **Kanidm / Dex / Zitadel** — Go/Rust based, lighter, but unnecessary extra    
infrastructure                                                                  
- **Shared database** — tight coupling, rejected early
